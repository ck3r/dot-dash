design notes

Why the site looks and behaves as it does. Most of this is one idea: a Morse station should feel like an instrument, something with a fixed shape that you learn with your hands.

a station, not a translator

A translator takes text and gives back dots. That's useful once. A station is somewhere you key, listen and practise, so the home page is the key itself, and the reference sits one tap behind it.

Underneath, the core only knows marks. Everything you see, hear or feel is a renderer hanging off the same few characters, so a new output never has to understand Morse.

           .-.
            │
   ┌────┬───┼────┬─────┐
 sound light buzz tree  tab

the look: bakelite and brass

The palette comes from a telegraph key: a black Bakelite base, brass contacts, and paper to write on. Every colour is a named token, and the light theme is the same instrument printed on paper.

  • bakelite
  • paper
  • graphite
  • wire
  • brass
  • dot
  • dash

Everything is monospace, for a practical reason: box-drawing lines only join up when every character is the same width, and the tree is drawn in them. System fonts come first, so most people download nothing. A small bundled subset catches the phones with no suitable font, where the tree would otherwise come apart.

Dot is short, small, red and on the left. Dash is long, large, blue and on the right. That holds everywhere: the tree, the two paddles, the colours. The logo is a schematic switch, which also reads as a dot and a dash, and it closes when the station keys.

one language for what can be touched

Every control speaks the same three states, so a new one needs no explaining:

grey    idle, or off
brass   under the pointer, or in focus
paper   on, or chosen

Brass is kept for that one job. Hover only exists where a real pointer does, so a phone never gets stuck showing a state left behind by a tap.

Controls are words rather than icons wherever there's room. Words read at a glance and suit the labelled-panel look. The narrowest phones swap "settings" for a gear, the one icon safe enough to stand alone.

object permanence

A real key doesn't rearrange itself between messages, and neither does the station. Controls stay where they are and change in place. Keying is muscle memory, so a button that moves costs more here than on most sites.

  • The player's readout has one fixed width, so the scrub bar never moves or changes length.
  • ⌫ and ↵ sit in the same place on the Morse pad and the text keyboard.
  • Switching an output off leaves its settings in place, greyed, and touching one switches it back on.
  • Suggestions are chips on the edge of a dial. They turn under the controls beside them instead of pushing them along, and always settle with one chip whole in the centre.

the tape

The message is a paper tape: each letter sits under its marks, placed under the second mark so it stays attached to its code as the line grows.

.... . .-.. .-.. ---
 H   E  L    L    O

Return feeds the line up into the history, like a typewriter. It sends nothing anywhere. A pause never ends a message either: on the air a pause is thinking, and a message ends on purpose.

The eye hides one side of the tape so you can practise copying, as a redaction bar rather than a blank. A tap goes between shown and redacted. A long hold collapses the row for room, and since collapsing is about space and not secrecy, nothing else is redacted then.

the tree as a hint

Morse is a binary tree: each mark is a step left or right, and the common letters sit near the top because they're the cheapest to send. Showing that is the fastest way to stop it feeling like a table to memorise.

At the station the whole tree would be too much, so the edge of the page shows a magnified piece: where you are, how you got there, and where you could go. Tap a child to key that mark.

  E      the letter before
  |      the step that got here
 [A]     here
 / \
R   W    tap one to key that mark

It's a hint rather than an answer, and playback keeps it that way. The tree can trace a letter mark by mark, but the rest waits. The about column holds the letter in grey, its marks fill in as they're sent, and the name only comes up when the letter lands.

sent     ▪      ▪      ▪
to come  ▫      ▪      ▪
         alfa   alfa   alfa
         grey   grey   landed

With playback set to voice, the letter lands whole as its name is said, because a name sounding halfway through keying its letter would give it away.

one code, several readings

The same marks can mean different things: .-.-. is both + and the prosign <AR>, and operators cut numbers down, so 599 goes out as 5NN. Meaning is a setting on top of the marks, so "pro" and "cut" change how a code reads, and a sent message keeps the reading it went with.

Typed cut digits need more care, since their marks are the same as a letter's. The typed text travels with the line, so a 9 stays a 9 even though it went out as an N.

Prosigns can act: keyed as one letter, <AR> returns the line and <HH> erases the word before it, as they do on the air. They only act when keyed. Typed, pasted or arriving in a link they stay text, so a message can never operate your station.

one signal

Everything that keys sends one signal, key closed or key open. Presses, taps, the keyboard and playback all go through it, and the lamp, the light and the vibration follow. Sound is the exception: it's scheduled ahead to stay exact.

Flashing is treated with care. The everyday light is the switch and a glow round the message, never the whole screen, so it's safe at any speed. The full-screen lamp asks first, and asks again, explicitly, if the message would flash more than 3 times a second, the photosensitivity guideline.

The browser tab keys too. It shows a link's message when one arrives, and keys the site's name while a message plays, since a tab icon can't keep pace with the message itself.

the link is the message

A message is its own address, so sharing needs no account and no database:

dot-da.sh/?/_...._.._
             h    i

Links stay Morse, which is half the fun of receiving one. Opening one puts the message on the line, ready to play. It doesn't start by itself, because browsers need a tap before sound, and that's the right order anyway. In a chat, a small Cloudflare Worker turns the link's preview into a card that keys the message.

What you key or type stays in your browser, history included, until you share it. A link carries its message in the address, so sharing is what sends it. The site is free, with no ads and no tracking, in the spirit of amateur radio.

how it's built

  • No build step. Static HTML, CSS and plain JavaScript modules, so what's on the server is what was written, and it stays easy to read and easy to keep running.
  • Light on old phones. The heavy parts load on first use: the whole tree, the about card, the file makers.
  • Offline, and never stale. The service worker goes to the network first, so you always get what's deployed, and keeps a copy for when there's no signal. Install it and it works as an app.
  • Checked in a real browser. Over a hundred Playwright checks run after every change. A refactor can then move code without moving behaviour, and CSS tidying is compared against style snapshots.
  • Comments say why. The code explains its reasons in plain words, often with a small sketch. Several on this page started as comments.

decided against

The ideas that didn't make it explain the design as well as the ones that did.

Sending on a long pause
A pause is thinking, and the station shouldn't guess.
Keyboard-style control codes
Some Morse keyboards use ..-- for space and .-.- for enter. Those codes are Ü and Ä, and the accented letters will need them.
Number and symbol colours at the station
They don't matter while transmitting, so they stay on the reference.
Saved files through the share sheet
The device already shares a downloaded file, and does it better.
Icons for everything
Share's icon differs by platform, and a clipboard can read as copy. Words don't have that problem.
